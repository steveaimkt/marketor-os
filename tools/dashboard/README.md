# 마케팅 OS 대시보드

로컬에서 **조직을 보고 · 일을 시키고 · 결과를 받는** 화면. 터미널·디스코드와 함께 3번째 사용 면이다.

## 이 대시보드가 맡는 범위 (2026-08-03 확정 · 정본)

세 단계로 나눠 쓴다. **어디까지가 대시보드 몫인지가 이 문서에서 가장 중요한 줄이다.**

| 단계 | 어디서 | 무엇을 |
|---|---|---|
| ① 초안에서 완성 문서까지 | **대시보드** | 시키고 · 고칠 점 적어 다시 받고 · 확인 완료로 문서를 확정 |
| ② 그 문서를 기준으로 한 후속 | **파트너사 (클로드 코드)** | 확정된 문서를 입력으로 삼아 별도 작업. 앞 세션을 이어받지 않는다 |
| ③ 완벽히 자동화될 만큼 굳은 업무 | **자동화 (cron·루틴)** | 반복이 확인된 것만 자동화 업무로 구축해 운영 |

그리고 대시보드의 나머지 절반은 **트래킹**이다. 내가 구축한 에이전트가 실제로 얼마나
쓰이고 있는지, 어디서 막히는지, 업무 효율이 어떤지를 본다. 지시 화면과 트래킹 화면이
한 곳에 있는 이유다.

### 여기 안 맞는 업무 (2026-08-03)

**파일을 먼저 넣고 그걸 읽어야 하는 일.** 이 대시보드엔 업로드 기능이 없다.
업로드한 CSV 분석, 원고 검토, 이미지 기반 작업이 여기 해당한다.

실측: 실업무 62건 중 파일 전제는 **2건(3%)** 이고 하나도 막히지 않았다.
이미 그런 일을 파트너사로 보내고 있었다는 뜻이다. 그 습관을 화면이 먼저 말해 준다
(게이트 1에서 파일 이야기가 나오면 안내가 뜬다 · **막지는 않는다**).

업로드를 붙이지 않는 이유: 파일을 다루는 일은 파일이 있는 곳에서 하는 게 맞다.
여기에 업로드를 붙이면 "여기서도 되네" 가 되고, 그 순간 3면 분담이 무너진다.

### 업무 생애주기 (2026-08-03 · 전략 1단계 반영)

```
시킨다 → 문서까지 완료 → 확인 완료 → 마무리 분류 ─┬─ 반복 안 함    → 보관
                                                  ├─ 반복될 것 같다 → 스킬로 굳히기
                                                  └─ 이미 굳었다   → 자동화
```

**시스템이 먼저 찍고 사람은 뒤집기만 한다 (2026-08-03)**

분류를 사람이 눌러야만 데이터가 쌓이면, 안 눌리는 순간 전략 전체가 멈춘다.
전례가 있다. 승인 버튼이 하나 있을 때 **42건 중 29건(69%)이 안 눌린 채** 방치됐다.

그래서 화면은 늘 추정을 채워 놓는다. 사람은 틀렸을 때만 고친다.

| | |
|---|---|
| 추정은 **저장하지 않는다** | 저장하면 나중에 "사람이 그렇게 판단했다" 와 구분이 안 된다. 읽을 때 계산한다 |
| 사람이 고른 값이 **언제나 우선** | 추정은 회색(`opacity:.62`) · 사람 값은 진하게. 눈으로 구분된다 |
| 근거를 같이 말한다 | "12회 반복 · 스킬 0%" · "이 담당을 2번 시켰습니다 · 3번은 넘어야 반복입니다" |

**"이 문서 썼나" 는 행동에서 얻는다.** 버튼을 늘리지 않는다.

| 신호 | 판정 |
|---|---|
| 발행함 (`publishedAt`) | 썼다 |
| **파트너사에서 열었음** (`openedAt`) | 썼다 · 이어서 작업했다는 뜻 |
| 후속이 붙음 | 썼다 |
| 산출물이 없음 | 못 썼다 |

지금 완료·산출물 있는 업무 76건 중 **17%가 클릭 없이 판정**된다.
`openedAt` 기록이 쌓일수록 이 비율이 올라간다.

마무리 분류에서 두 가지를 받는다. 둘 다 자동화 판정의 근거다.

| 받는 것 | 왜 |
|---|---|
| **이 문서 실제로 썼나** (`used`) | 반복 횟수만 세면 테스트성 업무가 후보로 올라온다. 실측에서 voc-analyzer 9회 중 6회가 테스트였다 |
| **앞으로 어떻게** (`automation`) | `none` · `skill` · `auto` |

**`skill` 이 따로 있는 이유**: 반복 업무의 스킬 사용률이 0~38%였다.
절차가 안 굳은 것을 자동화하면 제각각인 산출물을 매일 찍어낸다.
그래서 발견 → **스킬로 굳히기** → 자동화 3단으로 간다.

`GET /api/automation/candidates` 가 후보를 먼저 찾아 올린다.
기준은 **같은 담당 3회 이상 · 서로 다른 날 · 테스트성 제외**이고,
스킬 사용률이 60% 미만이면 자동화가 아니라 **스킬화를 먼저 권한다.**

⚠️ 이 판단은 기록의 양에 달렸다. `KEEP_TASKS` 를 40에서 400으로 올린 이유다
(40이던 시절엔 감사 파일 95건 중 40건만 보고 반복을 절반 넘게 못 셌다).

**왜 ①에서 끊나**
- 업무가 언제 끝나는지가 분명해진다. 후속을 체인으로 매달면 "완료"가 영영 오지 않는다
- 인계 단위가 대화 세션이 아니라 **파일**이 된다 (CLAUDE.md 산출물 착지 규약과 같은 방향)
- 세션 resume 은 시간이 지나면 깨지고, 체인이 길어질수록 앞 맥락을 매번 다시 실어 비싸진다
- 대신 문서에 안 적힌 맥락은 사라진다 · 그래서 **산출물이 그만큼 자족적이어야 한다**

**실측 근거 (2026-08-03)**

승인 항목이 붙은 업무 42건 중 **29건이 아무 것도 안 눌린 채 멈춰** 있었다.
주 버튼이 `승인하고 이어서 진행` 하나였고, 그게 두 가지를 한 버튼에 묶고 있었기 때문이다.

1. 내가 봤다 (공짜)
2. 다음 단계까지 실제로 시켜라 (새 실행 · $0.3~2)

누르면 뭐가 더 시작되는 버튼이라 망설이게 된다. 그래서 갈랐다.

| 버튼 | 무엇을 | 돈 |
|---|---|---|
| **확인 완료** (주·형광) | 봤고 됐다는 표시. 이 업무는 여기서 끝 | 안 든다 |
| **파트너사에서 열기** (완료 후 주) | 문서를 파트너사로 열고 붙여넣을 한 줄을 클립보드에 | 안 든다 |
| 고칠 점 적기 | 같은 담당이 같은 파일을 고쳐 다시 올린다 (완료 전 반복) | 든다 |
| 이대로 실행 (`그 외`) | 승인 항목대로 다음 단계까지 실제 실행 | 든다 |

여는 앱은 `Antigravity IDE` → `Antigravity` → 기본 앱 순으로 시도한다.
`DASHBOARD_EDITOR_APP` 을 넣으면 그것을 맨 앞에 놓는다.

| 면 | 도구 | 역할 |
|---|---|---|
| 파트너사 | Claude Code | 에이전트 **개선** (정의 수정·신규 제작) |
| **대시보드** | **이 폴더** | 에이전트 **사용** (지시·결과·승인) |
| 디스코드 | 클로드 채널 | 업무별 **소통** (외부·팀·고객) |

```bash
npm run dashboard          # → http://localhost:3737
open http://localhost:3737
```

이미 떠 있으면 브라우저만 열면 된다. 다른 포트는 `node tools/dashboard/server.mjs --port 3800`.

## 파일

| 파일 | 역할 |
|---|---|
| `server.mjs` | HTTP 서버 · 라우팅 · 정의파일 편집 · 산출물 열람 |
| `dispatch.mjs` | **업무 지시 실행기** · 지시를 `scripts/agent-runner.mjs` 자식 프로세스로 |
| `store.mjs` | **저장 계층** · Supabase Postgres 우선, 없으면 로컬 파일 |
| `config.mjs` | 사람이 정하는 값 (목표·예약페이지·영역·발행보드·꺼둔스킬·세팅) |
| `connections.mjs` | 도구 연결 진단 (등록 여부가 아니라 실제로 찔러 본다) |
| `jobs.mjs` | 자동화(launchd) 켜기·끄기·즉시실행 |
| `auth.mjs` | 인증 계층 (웹 공개 모드에서만 활성) |
| `index.html` | UI 전체 (단일 파일 · 빌드 없음) |

## 저장소 (2026-07-30 Supabase 연결)

업무 기록이 로컬 파일에만 있으면 맥과 VPS 가 서로 다른 목록을 본다. 웹으로 열려면 한 곳에 모여야 한다.

| 무엇 | 정본 | 사본 |
|---|---|---|
| 업무 기록 | `dashboard.tasks` | `outputs/tasks/*.json` (감사 기록 · DB 가 죽어도 남는다) |
| 수집 캐시 | `dashboard.cache` | `outputs/cache/*.json` |
| 설정 | `dashboard.config` | `brand/dashboard.json` (git 이력용) |

- **선택 백엔드다.** 접속 정보가 없으면 지금까지처럼 로컬 파일로 동작한다. 키가 없다고 대시보드가 죽지 않는다.
- 접속 정보는 `.env` 의 `DASHBOARD_DATABASE_URL` → 없으면 `~/.gbrain/config.json` 의 `database_url` 을 재사용한다.
  (비밀번호를 여러 파일에 복사하지 않으려는 의도. gbrain 이 이미 같은 Supabase 를 쓴다)
- **`dashboard` 스키마만 쓴다.** 이 Postgres 의 `public` 에는 gbrain 테이블이 74개 있다. 섞으면 서로를 망가뜨린다.
- 서버가 뜰 때 로컬 기록을 한 번 DB 로 이관하고, 그다음 기동부터는 DB 를 정본으로 읽는다.
- 기동 로그에 `🗄️ 저장: Supabase dashboard 스키마` 로 찍히면 정상. 설정과 연결 탭에도 표시된다.

## 재설계 (2026-08-01) · 일 시키는 도구로

메뉴를 9개에서 **4개(시키기 · 돌아가는 중 · 팀 · 설정)** 로 줄였다. 근거는 실측과 시장 패턴이다.

**실측 (지시 21건)**
- 방법론 100개를 갖춰 놓고 그걸로 시킨 건 1건 · 시키는 길이 카탈로그 안쪽에 묻혀 있었다
- 비슷한 지시 반복 7건 · 재사용 장치가 없었다 → 프리셋 저장 + 다시 시키기
- 소요 중앙값 13초, 최장 79초 · 그 사이 화면을 떠난다 → 완료 브라우저 알림 + 탭 제목 배지

**시장 패턴 (에이전트 대시보드 UX · 2026)**
- 미션 컨트롤: 어느 단계인지 보이고, 멈추고 다시 돌릴 수 있어야 한다 → 로그 스트림 + 중단 + 다시
- 사람 개입(HITL)은 제품 표면이어야 한다: 승인 큐를 전면에, 승인·거부를 1차 동작으로 → 돌아가는 중 상단 카드
- 완료·개입 필요 시점에 사람을 불러온다 → Notification + 탭 제목

뺀 화면(홈·캘린더·채널성과·메일함·Second Brain·카탈로그)은 코드로 남아 있다.
되살리려면 `NAV` 배열에 한 줄 넣으면 된다.

### Founder OS 참조 개편 (2026-08-01) · 방향과 돈

creator-os(thefounderos.com) 대시보드의 세 패턴을 이 OS 방식으로 옮겼다.

1. **전략 기둥 (TIES TO)** · 모든 업무는 5기둥(기업 강의 · 유튜브 · 온라인 강의 · 커뮤니티 · 운영) 중 하나에 묶인다.
   - 지시창에서 칩으로 고른다 (마지막 선택이 유지된다 · `localStorage mos.pillar`)
   - 실행 프롬프트에 `[방향]` 줄로 주입돼 에이전트가 산출물을 그 방향에 맞춘다
   - 표의 "무엇을 위해" 열 · 흐름 카드 배지 · 트루먼 줄의 기둥별 오늘 비용으로 돌아온다
   - 저장: `dashboard.tasks.pillar` 컬럼 (후속 지시는 부모의 기둥을 승계)
   - 기둥 목록은 `brand/dashboard.json`의 `pillars` (config.mjs 기본값)
2. **돈 최상단** · 돌아가는 중 맨 위 KPI 4타일: 이번 달 수입(수동 장부) · 오늘 AI 비용(실측) · 내 승인 차례 · 오늘 끝남.
   수입 자동 수집은 없으므로 **없는 숫자를 만들지 않는다** · 기록이 없으면 "기록 없음"으로 정직하게 비운다.
3. **QUICK ACTION** · 사이드바 "수입 기록"(₩ 장부 · `moneyEntries`) · "기억해 두기"(한 줄 → 트루먼 low effort로 gbrain 기록).

미뤄 둔 것: behind-pace(목표 대비 진도)와 수입 자동 KPI는 실데이터 연결 후. 추정치로 채우지 않는다.

## 화면 (Claude Design 목업 이식 · 2026-07-30)

UI 정본은 claude.ai/design 프로젝트 **마케팅 OS 대시보드 UI 목업**
그 목업은 Design Component 런타임용이라 그대로 쓰지 않고, 마크업과 스타일 값을 참조해
**빌드 없는 단일 HTML + 바닐라 JS** 로 다시 구현했다 (핸드오프 지시).

### 목업과 다르게 한 것 (이유 포함)

| 항목 | 목업 | 이 구현 | 왜 |
|---|---|---|---|
| 아이콘 | Lucide CDN | 인라인 SVG | 이 대시보드는 외부 요청이 0이어야 한다 (오프라인에서도 안 깨지게) |
| 비용 표기 | 원화 | 달러 | 서버가 주는 값이 달러다. 환율을 임의로 곱하면 없는 숫자를 만든다 |
| 지시 모드 | 4종 | 5종 (스킬 추가) | 서버가 스킬 지시를 지원한다. 기능을 버릴 이유가 없다 |
| 카탈로그 카드 클릭 | 바로 실행 | 채팅에 넣기 | 한 번 클릭에 돈이 나가면 안 된다. 보내기를 눌러야 실행 |
| 그리드 | `repeat(N,1fr)` | `repeat(N,minmax(0,1fr))` | `word-break:keep-all` 한글이 안 쪼개져 min-content 가 컬럼을 밀고 우측 패널을 덮었다 |

### 탭 8개 (2026-08-03 현행 · 정본은 `index.html` 의 `NAV` 배열)

사이드바 순서가 정보 우선순위다. 이 순서를 바꾸지 않는다.

| 탭 | 무엇을 |
|---|---|
| **업무 요청하기** | 지시의 단일 입구 · 무엇을 → 누구에게 → 어떻게 → 확인 |
| **업무 현황** | 일간·주간·월간 + 마감 |
| **이슈 사항** | 막힌 것 · 개선하면 좋은 것 |
| **팀 협업** | 어느 팀이 무엇을 하고 있나 · 진행 중 → 확인 → 완료 → 보관 |
| **팀 미팅** | 한 팀과 이어서 주고받기 |
| **팀 도구** | 방법론 100 · 내 맞춤 스킬 |
| **자동화 업무** | 예약(켜기·끄기·즉시실행) · 하네스 업무 · 검증 루프 |
| **팀 점검** | 팀 운영 · 주간 · 월간 돌아보기 |
| (사이드바 하단) **설정** | 도구 연결 · 실행 위치 · 내 일정 · 정의 파일 편집 |

**한 가지는 한 곳에만 둔다 (2026-08-03 중복 정리)**

같은 목록이 두 탭에 그려지고 있었다. 조작이 있는 쪽을 정본으로 남기고 사본을 지웠다.

| 무엇 | 정본 | 지운 사본 |
|---|---|---|
| 자동화 예약 | **자동화 업무** 탭 (목록 + 켜기·끄기·즉시실행) | 설정 탭의 같은 목록 · 팀 도구 탭의 읽기 전용 복사본 |
| 외부 도구(MCP) | **설정** 탭 (상태 + 고치는 방법) | 팀 도구 탭의 읽기 전용 복사본 |

지운 자리에는 한 줄 요약과 그 탭으로 가는 링크만 남겼다.
사본이 되살아나는지는 `scripts/doctor.mjs` 의 `ABSENT` 집합이 감시한다.

우측 **업무 채팅**(기본 열림)이 지시의 단일 입구다. 드로어에서 업무 로그·산출물·정의 파일을 본다.

### 데이터는 어디서 오나 (2026-07-30 전부 연결)

서버는 의존성 없는 순수 node 라 MCP 를 직접 못 부른다. 그래서 두 갈래로 나눴다.

| 갈래 | 무엇 | 어디에 저장 |
|---|---|---|
| **내가 정하는 값** | 채널 목표·예약 페이지·사업 영역·발행 보드·꺼둔 스킬·첫 세팅 답변 | `brand/dashboard.json` (`config.mjs`) |
| **밖에서 읽어오는 값** | 채널 성과·내 일정·미팅 요청·기억 | `outputs/cache/*.json` (`scripts/collect.mjs`) |

수집은 에이전트가, 서비스는 서버가 한다. 화면의 **지금 수집하기** 버튼이 `scripts/collect.mjs` 를
자식 프로세스로 띄우고, 그 안의 Claude Agent SDK 세션이 MCP 를 써서 JSON 을 남긴다.

```bash
npm run collect channels     # 채널 성과
npm run collect schedule     # 내 일정
npm run collect meetings     # 미팅 요청
npm run collect brain        # Second Brain
npm run collect:all          # 전부
```

- 수집기는 **읽기 전용**이다. 발행·전송·삭제·예산 변경을 금지하는 규약을 프롬프트에 건다.
- **값을 모르면 비운다.** 그럴듯한 숫자를 만들지 않고, 왜 비었는지 `notes` 에 적어 화면에 그대로 보여 준다.
- 유튜브는 예외로 **노드가 직접** 읽는다 (`.env` 의 API 키 · 공짜·즉시·MCP 인증과 무관).
- 수집 1회당 대략 $0.3에서 2, 1분에서 3분.

### 연결 상태는 추측하지 않는다

`GET /api/connections` 가 실제로 찔러 본다 (`connections.mjs`). 설정과 연결 탭에 세 가지로 나온다.

| 상태 | 뜻 |
|---|---|
| 정상 | 지금 값을 받아왔다 (실측) |
| 에이전트 경유 | 노드에서 확인은 못 하지만 에이전트가 MCP 로 쓴다 |
| 손봐야 함 | 사람이 한 번 손대야 한다 · **고치는 방법** 버튼에 명령이 들어 있다 |

2026-07-30 실측 결과: 유튜브와 디스코드는 정상, 구글 캘린더와 Second Brain 은 에이전트 경유로 수집 성공,
**GA4 만 브라우저 재로그인이 필요**했다 (`invalid_rapt`). Gmail 은 커넥터가 안 잡혀 미팅 요청이 비어 있다.

## 업무 지시

터미널을 열지 않고 대시보드에서 지시하면 **실제로 실행**된다. 엔진은 Claude Agent SDK.

| 모드 | 무엇 | 어떻게 실행되나 |
|---|---|---|
| 🧠 트루먼에게 | 자연어 한 줄 · 부서 몰라도 됨 | orchestrator 가 받아 라우팅 |
| 🤖 담당자 지정 | 조직도에서 담당 골라 직접 | 그 에이전트 정의를 systemPrompt 로 |
| ⌨️ 체인 | `100-skills/ROUTING.md` §체인 15종 | 「○○ 돌려줘」 를 프롬프트로 (슬래시 아님) |
| 🧩 스킬 | `skills/` 지정 | Skill 도구로 그 절차 실행 |
| 👥 팀 소집 | 표준 편성 3종 | team-run 절차 + 파일 착지 규약 주입 |
| ↩️ 이어서 지시 | 끝난 업무에 후속 요청 | **같은 세션 resume** · 앞 맥락을 기억한다 |

> ↩️ 이어서 지시는 **완료 전 수정 반복용**이다. 문서가 확정된 뒤의 후속은 위 "이 대시보드가
> 맡는 범위" 대로 클로드 코드에서 그 문서를 들고 한다. 세션 체인을 길게 끌지 않는다.

- 진행 로그·턴·비용·산출물이 카드에 실시간 표시 (2.5초 폴링) · 중단 버튼 제공
- `⏸ 승인 필요` 항목이 있으면 카드에 체크리스트로 뜨고, **승인하고 발행까지 진행** 버튼으로 이어간다
- 감사 기록: `outputs/tasks/{id}.json` (프롬프트·로그 전문)
- **비용**: 지시 1건당 대략 **$0.3~2**. 에이전트 정의 + CLAUDE.md + MCP 12개 스키마를 매번 싣기 때문. 조회·수집은 "경량 모드"를 켜라.

### 안전 (CLAUDE.md 헌법)

- `permissionMode` 는 **acceptEdits 고정** · `bypassPermissions` 를 쓰지 않는다
- 기본값 **초안까지만** · 발행·전송·예약·광고 예산 변경·삭제는 프롬프트로 차단
- "발행·전송까지 허용" 체크박스는 확인 대화를 한 번 더 거친다 · 그래도 예산 변경·삭제는 계속 차단
- 헤드리스라 되물을 수 없으므로 "가정을 명시하고 진행" 규약을 주입한다
- 대상은 화이트리스트 검증 (등록된 에이전트명 · 존재하는 스킬·체인 · 정의된 편성)
- `spawn` 은 셸 없이 배열 인자 → 커맨드 인젝션 불가
- 동시 3건 상한 · 20분 타임아웃

## 웹에서 접근하게 만들기

⚠️ 이 대시보드는 **명령을 실행하는** 도구다. 인증 없이 노출되면 남이 내 계정으로 에이전트를 돌리고 파일을 쓸 수 있다.
그래서 루프백이 아닌 주소에 바인딩하려는데 비밀번호가 없으면 **서버가 아예 뜨지 않는다** (fail-closed).

### 1) 비밀번호 설정

`.env` 에 넣는다. 평문보다 해시를 권한다.

```bash
node tools/dashboard/server.mjs --hash-password '고른비밀번호'
# 출력된 DASHBOARD_PASSWORD_HASH=... 한 줄을 .env 에 붙인다
```

```bash
# .env
DASHBOARD_PASSWORD_HASH=scrypt$16384$8$1$...
DASHBOARD_ALLOWED_HOSTS=dash.example.com
DASHBOARD_SECURE_COOKIE=true      # HTTPS 뒤에 둘 때
```

평문으로 빨리 시험만 할 거면 `DASHBOARD_PASSWORD=...` 도 받는다 (서버가 기동 시 해시화).

### 2) 띄우기

```bash
node tools/dashboard/server.mjs --host 0.0.0.0 --port 3737
# 모드: 🔐 공개 (비밀번호 로그인 + 세션 + CSRF 토큰) 이라고 찍히면 정상
```

### 3) HTTPS 는 리버스 프록시로

서버 자체는 평문 HTTP다. 쿠키가 그대로 흐르면 안 되니 **반드시** 프록시 뒤에 둔다.

```
# Caddyfile (인증서 자동)
dash.example.com {
    reverse_proxy 127.0.0.1:3737
}
```

프록시를 쓸 때는 대시보드를 `--host 127.0.0.1` 로 두고 프록시만 외부에 노출하는 것이 가장 안전하다.
그러려면 비밀번호가 설정돼 있어야 로그인이 활성되므로, `.env` 에 비밀번호를 넣고 `127.0.0.1` 바인딩을 유지하면 된다.

### 4) 집 안에서 먼저 (폰·아이패드 · 5분)

```bash
node tools/dashboard/server.mjs --hash-password '고른비밀번호'   # 해시를 .env 에
# .env
# DASHBOARD_PASSWORD_HASH=scrypt$...
# DASHBOARD_ALLOWED_HOSTS=192.168.0.10,내맥이름.local
node tools/dashboard/server.mjs --host 0.0.0.0
```

같은 와이파이에서 `http://<맥IP>:3737` 로 붙는다. 로그인 화면이 먼저 나오면 정상이다.
IP 는 DHCP 로 바뀔 수 있으니 `.local` 호스트명도 함께 화이트리스트에 넣어 둔다.

### 5) VPS 로 옮기기 (밖에서도)

24시간 상시 가동은 맥이 아니라 VPS다 (맥 launchd 는 슬립·권한 문제로 실패가 잦다).
자산은 `automation/dashboard-vps/` 에 있다.

```bash
bash automation/dashboard-vps/deploy.sh root@<host> /root/marketing-os 22
```

스크립트가 하는 일 · 전제 확인(git·node 20+) → git pull 또는 clone → npm install →
`.env` 를 표준입력으로 복사(ps 에 비밀값이 남지 않게) → systemd 등록·기동 → 상태 출력.

스크립트가 **하지 않는** 일 두 가지는 사람이 해야 한다.

1. **Claude 인증** · VPS 에서 한 번 로그인하거나, 맥에서 `claude setup-token` 으로 받은 값을
   VPS `.env` 의 `CLAUDE_CODE_OAUTH_TOKEN` 에 넣는다.
   확인: `node scripts/sdk-p.mjs -p "1+1은? 숫자만"` 이 2 를 뱉으면 통과.
2. **HTTPS** · `automation/dashboard-vps/Caddyfile.example` 을 참고해 Caddy 를 세운다.
   앱은 `127.0.0.1` 에만 바인딩하고 프록시가 외부를 맡는다 (공격면을 좁힌다).
   프록시 뒤에서는 `.env` 에 `DASHBOARD_SECURE_COOKIE=true` 를 켠다.

Supabase 를 쓰고 있으면 맥과 VPS 가 **같은 업무 목록**을 본다. 다만 산출물 파일 실물은
아직 각 기계의 `outputs/` 에만 있다 (DB 에는 경로만). 파일까지 공유해야 하면 Supabase Storage 를 붙인다.

### 남은 숙제 (웹 공개 전 결정할 것)

- **다중 사용자**: 지금은 비밀번호 1개 = 사용자 1명. 팀에게 열려면 계정·권한 분리가 필요하다
- **지시 권한 분리**: 누구는 조회만, 누구는 지시까지 — 현재는 로그인하면 전부 가능
- **비용 상한**: 지시 1건당 $0.3~2 · 외부에 열면 지출 상한·쿼터가 필요하다
- **감사 추적**: `outputs/tasks/` 에 남지만 "누가" 는 안 남는다 (단일 사용자 전제)
