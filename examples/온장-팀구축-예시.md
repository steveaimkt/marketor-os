# 예시 · 「온장」 수제 구움과자 브랜드 팀 구축

> **이 파일의 용도**: 「팀 구축하자」부터 「팀 실행하자」까지 **한 회사가 실제로 밟는 전 과정**을
> 처음부터 끝까지 보여주는 교보재. 가상 회사 하나로 6게이트 + 4게이트를 완주했다.
> **여기 나오는 회사는 실재하지 않는다.** 절차와 판단 근거를 보여주기 위한 예시다.
>
> 작성 2026-08-03 · 실제로 배포판 사본에 배선해 화면 렌더까지 확인한 기록이다.

## 왜 이 예시가 필요한가

같은 창고(AI 직원 58 + 방법론 100)에서 **회사마다 완전히 다른 팀이 나온다**는 것을
말로 설명하면 안 믿는다. 그래서 두 회사를 나란히 놓는다.

| | 원저자 회사 (교육·컨설팅·1인) | **온장** (커머스·오프라인·직원 3) |
|---|---|---|
| 팀 | 5팀 46명 | **3팀 15명** |
| 최다 카테고리 | 09 브랜드세일즈 | **06 커머스** |
| 안 만든 팀 | 광고 · 커머스 | **광고 · 콘텐츠** |
| 첫 업무 | 데일리 리뷰 | **스마트스토어 진단** |

**코드는 한 줄도 다르지 않다.** `brand/dashboard.json > deptTeams` 한 곳만 다르다.

# 1단계 · 구축 (게이트 6개)

## 게이트 1/6 · 지금 어떻게 굴러가나

| 질문 | 답 |
|---|---|
| 마케팅을 **누가** 하나 | 사장(총괄, 마케팅 절반) · 마케팅 담당 1명(입사 6개월, 주로 인스타) · 매장 알바 2명(마케팅 무관) |
| **반복되는 일** | 인스타 주 4~5회 · 블로그 주 1회 · 스마트스토어 상세 수정 수시 · 월말 정산 리포트 |
| **안 하는 것** | 광고 집행(작년에 해보고 접음) · 이메일 · 커뮤니티 · 유튜브 |

> **사업이 아니라 운영을 묻는다.** "무엇을 파나 · 매출이 어디서 나오나"는 팀 편성의 직접 근거가
> 아니고 답하기도 부담스럽다. "지금 이 일을 누가 어떻게 하고 있나"가 곧바로 팀이 된다.

## 게이트 2/6 · 무엇이 막혀 있나

| 질문 | 답 |
|---|---|
| 손이 못 미쳐 **못 하는 일** | 경쟁사 뭐 하는지 볼 시간이 없음 · 고객 리뷰를 모아본 적 없음 |
| 시간이 **너무 드는 일** | 상세페이지 카피 1건에 반나절 · 월말 리포트 하루 꼬박 |
| 계속 **미루는 일** | 재구매 유도(카톡·문자) · 시즌 기획(추석·설) |

## 게이트 3/6 · 실측 (질문 없음)

```
업무 기록:  0건   ← 첫 구축이라 없다
조직 감사:  AI 직원 58명 · 아무도 배치 안 됨
gbrain:     미연결

→ 실측할 게 없다. 게이트 4는 방법론 100 대조로 진단한다.
```

**첫 사용자는 기록이 없다.** 이 상황이 정상이고, 그래서 방법론 대조가 필요하다.

### 여기서 나온 결론 3가지

**① 팀 후보** (○+△ 5개 이상)
06 커머스 9 · 02 제품기획 8 · 04 소셜 6 · 01 시장조사 6 · 08 CRM 5 · 07 분석 5

**② 공백** (○인데 담당 없음) → 각 팀의 첫 업무가 된다
054 리뷰 관리 · 055 스마트스토어 진단 · 053 상품명 최적화 · 006 리뷰 마이닝 · 003 경쟁사 모니터링 · 065 RFM

**③ 팀 만들지 않음**
`05 광고 ✕10` → 광고팀 없음 · 관련 인원 전원 대기
`03 콘텐츠 ✕6` → 유튜브·뉴스레터·링크드인 담당 대기

> **교차 확인**: 게이트 2의 "경쟁사 볼 시간 없음"·"리뷰 모아본 적 없음"이
> 대조표의 공백 ②와 정확히 일치했다. 사람 말과 방법론 대조가 같은 답을 가리키면 확신할 수 있다.

# 2단계 · 팀 실행 (게이트 4개)

## 게이트 1/4 · 배선

`brand/dashboard.json` 에 실제로 옮긴 값 (발췌).

```jsonc
"deptTeams": [
  { "lead": "brand-sales-lead", "name": "커머스팀",
    "groups": ["commerce", "part5-copy", "product"],
    "cats": ["06-commerce", "02-product"],
    "roster": ["landing-copy","design-producer","funnel-optimizer",
               "promo-planner","offer-designer","quality-reviewer-6axis"] },
  { "lead": "research-lead", "name": "고객·시장팀",
    "cats": ["01-research", "07-analytics", "08-crm"],
    "roster": ["voc-analyzer","competitor-monitor","ga4-analyzer","crm-lead"] },
  { "lead": "content-lead", "name": "소셜팀",
    "cats": ["04-social", "03-content"],
    "roster": ["sns-orchestrator","content-planning"] }
],
"pillars": [
  { "key": "store", "name": "자사몰" }, { "key": "smartstore", "name": "스마트스토어" },
  { "key": "b2b", "name": "B2B 답례품" }, { "key": "ops", "name": "운영" }
]
```

**주의**: `roster`·`target` 슬러그는 `agents/` 에 **실존하는 이름만**. 오타 하나면 그 사람이 화면에서 사라진다.

## 게이트 2/4 · 배선 검증

```
✅ 커머스팀 · 팀원 6 · 업무 4
✅ 고객·시장팀 · 팀원 4 · 업무 4
✅ 소셜팀 · 팀원 2 · 업무 2

✅ 배선 정상 · 게이트 3으로
```

그다음 **눈으로** 확인했다. 대시보드 팀 화면을 렌더해 보니 온장 3팀이 떴고
"아직 팀이 없습니다"가 사라졌다. (37,170자 렌더 · 커머스팀 표시 확인)

## 게이트 3/4 · 팀별 사용 카드

`brand/team-cards.md` 로 착지. **부를 때 문장**이 핵심이다.

```
## 커머스팀 · 7명
- 하는 일: 상세페이지·상품명·프로모션·전환
- 부를 때: "스마트스토어 진단해줘" · "상세페이지 카피 한 벌" · "추석 프로모션 짜줘"
- 사람 몫: 최종 문구 확정 · 가격 결정 · 발행
- AI 몫: 초안·진단·구성안
- 첫 업무: 스마트스토어 진단 (055)
```

## 게이트 4/4 · 시동 (여기서 멈춤)

```
🔴 커머스팀    · 실행 0건 · 산출물 0건  ← 첫 업무: 스마트스토어 진단
🔴 고객·시장팀 · 실행 0건 · 산출물 0건  ← 첫 업무: 고객 리뷰 마이닝
🔴 소셜팀      · 실행 0건 · 산출물 0건  ← 첫 업무: UGC 수집·활용

0/3 팀 시동 · 팀 실행 미완
```

**이 예시는 여기서 멈춘다.** 온장은 가상 회사라 진단할 스마트스토어도, 분석할 리뷰도 없다.
실제 사용자라면 여기서 첫 업무 3건을 돌리고 **산출물이 나와야** 팀 실행이 끝난다.

> **"첫 업무를 한 번 시켜 본다. 안 돌면 받은 게 아니다."**

# 이 예시에서 배울 것 4가지

**① 안 하는 것을 말하면 팀이 줄어든다**
광고를 ✕10으로 판정했더니 광고팀이 통째로 안 생겼다. 관련 인원 22명이 대기로 갔다.
"혹시 나중에 쓸까 봐" 만들어 두면 안 쓰는 팀이 화면을 채운다.

**② 공백이 첫 업무가 된다**
"○ 인데 담당 없음"이 그 팀의 첫 업무다. 지금 아무도 안 하던 일이 처음 돌아가는 것이라
효과가 바로 보이고, 시동이 걸린다.

**③ 검토층이 팀을 줄인다**
4팀 → 3팀. 운영 시니어의 "4팀에 사람이 1.5명"이 결정적이었다.
편성은 만드는 쪽으로 기울기 쉬워서, 줄이는 시선이 따로 필요하다.

**④ 승인과 가동은 다르다**
게이트 6 승인 후에도 화면은 빈 팀이었다. 배선 7곳을 하고 나서야 팀이 떴고,
그 뒤에도 시동을 안 걸면 **팀 명단만 있고 아무도 안 쓰는** 상태가 된다.
그래서 팀 실행이 독립 단계다.
