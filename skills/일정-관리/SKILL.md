# 일정 관리 · 커넥터 제약을 인정한 현실 설계

## 왜 이런 구조인가 (정직한 전제)
구글 캘린더·Akiflow·Gmail 은 claude.ai 통합(OAuth 커넥터)이라 **대시보드가 띄우는 헤드리스 실행에는 그 도구가 없다.**
그래서 "대시보드가 캘린더를 직접 읽는다"는 구현은 불가능하다. 대신 두 갈래로 나눈다.

## A. 당겨오기 (대화형에서 · 하루 1회면 충분)
대표이 터미널·데스크탑 클로드에서 이 스킬을 부르면:
1. Google Calendar(list_events) 또는 Akiflow(get_schedule)로 **오늘~14일** 일정을 읽는다.
2. 다음 형식으로 `brand/schedule.json` 에 쓴다 (덮어쓰기):
```json
{ "collectedAt": "ISO", "source": "google-calendar 또는 akiflow",
  "events": [ { "start": "2026-08-03T10:00", "end": "...", "title": "...", "kind": "강의|미팅|촬영|기타" } ] }
```
3. 읽지 못하면 events 를 비우고 `note` 에 이유를 적는다. **일정을 지어내지 않는다.**

## B. 쓰기 (대시보드·업무에서)
- 대시보드 확인 탭 캘린더 뷰가 `brand/schedule.json` 을 읽어 마감·발행과 함께 보여준다.
- 업무 지시 때 "이번 주 일정과 겹치지 않게" 같은 판단이 필요하면 이 파일을 근거로 쓴다.
- 파일이 없거나 오래됐으면(24시간 초과) **"일정이 오래됐습니다 · 당겨오기를 먼저 해주세요"** 라고 알린다.

## 판단 규칙 (일정 → 업무)
- 강의·촬영이 있는 날은 무거운 업무(하네스·영상 기획)를 배치하지 않는다.
- 마감 D-1 인데 그날 일정이 3건 이상이면 **전날로 당기라고 제안**한다.
- 빈 슬롯(2시간 이상)이 있으면 밀린 승인·발행을 그 시간에 제안한다.
