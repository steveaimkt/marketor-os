# 팀 피드백하자 · 이 팀이 실제로 돌고 있나

> 구축은 한 번이고 운영은 매주다. 편성이 맞아도 안 쓰면 없는 팀이다.
> 이 스킬은 **묻기 전에 센다.** 사람에게 "잘 돌아가나요"라고 되묻지 않는다.

## 0단계 · 모드 판별 (자동 · 묻지 않는다)

```
deptTeams 가 비었나?
   ├─ 예 (또는 게이트 진행 중) →  구축 전 · "세팅이 맞나"
   └─ 아니오 (팀이 있다)
         └─ 마지막 팀 피드백이 언제였나?
               ├─ 21일 미만        →  주간 · "일이 돌았나"    (조직 안 건드림)
               └─ 21일 이상 · 처음  →  월간 · "편성이 맞나"    (재편성까지)
```

```bash
# 마지막 점검일 (파일명 기준 · 없으면 아무것도 안 나온다 = 첫 점검 = 월간)
# ⚠️ ls + 글롭을 쓰지 않습니다. 매치가 없을 때 zsh 가 "no matches found" 로 죽는다.
find outputs -type f \( -name '팀-피드백-*.md' -o -name '세팅-피드백-*.md' \) 2>/dev/null | sort | tail -1
```

출력이 **비어 있으면 첫 점검이다 → 월간.** 파일이 있으면 경로의 날짜와 오늘을 비교해 21일로 가른다.

한 줄로 알리고 시작한다. 예: `주간으로 봅니다 (마지막 점검 8일 전 · 조직은 안 건드립니다)`

**사용자가 명시하면 그쪽을 따른다.** "이번 달 점검" 이라고 하면 21일이 안 지났어도 월간으로 본다.

### 주간과 월간이 다른 점

| | **주간** (금요일 권장) | **월간** |
|---|---|---|
| 묻는 것 | **일이 돌았나** | **편성이 맞나** |
| 실측 | ①②③ 만 (가동률·처리량·막힌 곳) | **6종 전부** + 성장 트리거 |
| 고칠 것 | **1~2개** · 그 주에 처리할 수 있는 것 | **3개 이내** · 구조까지 |
| 조직 | **안 건드린다** · 보관·신설·재편성 제안 금지 | 대기·신설·보관·재편성 판단 ⏸ |
| 넘기는 곳 | 없음 (그 주에 끝낸다) | 「팀 구축하자」·「직원 다운로드」·「스킬 다운로드」 |
| 걸리는 시간 | 1~2분 | 5~10분 |

> **주간에 조직 얘기를 꺼내지 않는다.** 매주 편성을 흔들면 팀이 자리를 못 잡는다.
> 주간에 구조 문제가 보이면 **적어만 두고** 월간으로 넘긴다 (`다음 월간에 볼 것:` 한 줄).

# 구축 전 모드 · 세팅이 맞나

아직 실적이 없으니 **실측할 게 없다.** 대신 **세팅의 논리**를 본다.
승인 직전 한 번이 아니라 **게이트 진행 중 아무 때나** 부를 수 있다. 그게 이 모드의 존재 이유다.

## 볼 것 6가지

| # | 무엇 | 어디서 | 빨간불 |
|---|---|---|---|
| ① | **근거 있는 팀인가** | 편성안의 팀마다 게이트 4 대조표 숫자가 붙었나 | 근거 없이 만든 팀 1개 이상 |
| ② | **공백이 첫 업무로 갔나** | ○ 인데 담당 없음 항목이 어느 팀 첫 업무인가 | 공백인데 아무 팀도 안 맡음 |
| ③ | **안 하는 걸 만들었나** | ✕ 10개인 카테고리에 팀이 있나 | 있으면 그 팀은 빈 팀이 된다 |
| ④ | **팀원 없는 팀** | 팀장만 있는 팀 | 1개 이상 (부서는 부서가 아니다) |
| ⑤ | **처리 방식 지정** | 업무마다 ⓐ/ⓑ/ⓒ 가 붙었나 | 미지정 항목 있음 |
| ⑥ | **성장 트리거** | 관측 담당·주기·판정이 다 적혔나 | 조건만 있고 관측 담당 없음 |

## 세는 법

```bash
node -e "
const fs=require('fs');
const d=JSON.parse(fs.readFileSync('brand/dashboard.json','utf8'));
const T=d.deptTeams||[];
if(!T.length){console.log('아직 편성 없음 · 편성안 파일을 직접 읽어 판정한다');process.exit(0)}
for(const t of T){
  const w=(d.deptWork||{})[t.name]||[];
  const flags=[];
  if(!t.roster||!t.roster.length) flags.push('④ 팀원 없음');
  if(!t.cats||!t.cats.length) flags.push('① 담당 방법론 미지정');
  if(!w.length) flags.push('② 시킬 수 있는 일 0건');
  if(w.some(x=>x.harness===undefined)) flags.push('⑤ 처리 방식 미지정 '+w.filter(x=>x.harness===undefined).length+'건');
  console.log((flags.length?'🔴 ':'✅ ')+t.name+' · 팀원 '+(t.roster||[]).length+' · 업무 '+w.length+(flags.length?' · '+flags.join(' / '):''));
}
"
```

# 구축 후 모드 · 실제로 도나

## 원칙

1. **실측만 쓴다.** 세지 못한 것은 "측정 안 됨"으로 비워 둡니다. 느낌을 숫자처럼 쓰지 않는다.
2. **고칠 지점은 주간 1~2개 · 월간 3개 이내.** 다 나열하면 아무것도 안 고친다. 가장 아픈 것부터.
3. **사람 몫과 시스템 몫을 가른다.** 승인이 밀린 건 사람 몫, 배관이 끊긴 건 시스템 몫이다.
4. **대신 고쳐 주지 않는다.** 진단하고 처방까지. 실행은 ⏸ 승인 후 별건으로.
5. 결과는 파일로 먼저 착지시킨다 (`_conventions.md §I`).
6. **주간은 조직을 안 건드린다.** 보관·신설·재편성 제안을 하지 않는다. 적어만 두고 월간으로 넘긴다.

## 1단계 · 실측 (질문 없이 먼저 센다)

무엇을 세고 있는지 한 줄로 알리고 시작한다. **주간은 ①②③ 만 센다.**

| # | 무엇 | 주간 | 어디서 | 무엇을 본다 |
|---|---|:--:|---|---|
| ① | **가동률** | ✅ | `outputs/tasks/*.json` | 편성된 사람 중 최근 호출 기록이 있는 비율 · 팀별 |
| ② | **팀별 처리량** | ✅ | 같음 | 팀마다 몇 건 · 마지막 실행일 · 30일 이상 조용한 팀 |
| ③ | **막힌 곳** | ✅ | 같음 | 확인 안 한 건수와 가장 오래된 것 · 실패(`status: error`) |
| ④ | **끝맺음** | — | 같음 | 산출물이 나온 건 중 실제로 **발행·전달된 비율** |
| ⑤ | **배관** | — | `agents/**/*.md` | `Agent(x)` 소집 선언 중 보관·부재 인원을 부르는 것 (**죽은 소집**) |
| ⑥ | **성장 트리거** | — | `brand/my-team.md` | 각 트리거가 임계에 닿았는지 · 관측 담당이 실제로 봤는지 |

> 주간에 ④⑤⑥ 을 빼는 이유: 발행 비율·배관·성장 트리거는 **한 주로는 안 움직인다.**
> 매주 세면 같은 숫자를 다시 보고 같은 처방을 반복하게 된다.

### 세는 법 (그대로 써도 된다)

```bash
# ①②③④ 업무 기록 전수
node -e "
const fs=require('fs');
const T=fs.readdirSync('outputs/tasks').filter(f=>f.endsWith('.json'))
  .map(f=>{try{return JSON.parse(fs.readFileSync('outputs/tasks/'+f,'utf8'))}catch(e){return null}}).filter(Boolean);
const cfg=JSON.parse(fs.readFileSync('brand/dashboard.json','utf8'));
const cnt={}; for(const t of T){const k=t.runnerAgent||t.target; if(k)cnt[k]=(cnt[k]||0)+1;}
for(const team of cfg.deptTeams||[]){
  const ss=[team.lead,...team.roster];
  const used=ss.filter(s=>cnt[s]);
  const n=T.filter(t=>ss.includes(t.runnerAgent||t.target));
  const last=n.length?new Date(Math.max(...n.map(t=>t.startedAt||0))).toISOString().slice(0,10):'없음';
  console.log(team.name+' · 가동 '+used.length+'/'+ss.length+'명 · 처리 '+n.length+'건 · 마지막 '+last);
}
const wait=T.filter(t=>t.approvals&&t.approvals.length&&!t.approvalsHandled);
const withOut=T.filter(t=>t.outputFile||(t.outputFiles||[]).length);
console.log('막힘: 확인 대기 '+wait.length+'건 · 실패 '+T.filter(t=>t.status==='error').length+'건');
console.log('끝맺음: 산출 '+withOut.length+'건 중 발행 '+withOut.filter(t=>t.publishedAt).length+'건');
"

# ⑤ 죽은 소집 (가동 중인 에이전트가 보관·부재 인원을 부르는 것)
#    ⚠️ 부르는 쪽도 _archive 를 빼야 한다. 안 빼면 보관끼리의 호출이 오탐으로 잡힌다.
node -e "
const fs=require('fs'),path=require('path');
const live=new Map(),arc=new Set();
(function w(d,a){for(const e of fs.readdirSync(d,{withFileTypes:true})){const fp=path.join(d,e.name);
 if(e.isDirectory()){w(fp,a||e.name==='_archive');continue;}
 if(!e.name.endsWith('.md'))continue;
 const txt=fs.readFileSync(fp,'utf8');
 const nm=(txt.match(/^name:\s*(.+)\$/m)||[,''])[1].trim(); if(!nm)continue;
 if(a)arc.add(nm); else live.set(nm,txt);}})('agents',false);
const rostered=new Set((JSON.parse(fs.readFileSync('brand/dashboard.json','utf8')).deptTeams||[])
  .flatMap(t=>[t.lead,...t.roster]));
let dead=0,bench=0;
for(const [nm,txt] of live){
  for(const c of new Set([...txt.matchAll(/Agent\(([a-z0-9-]+)\)/g)].map(m=>m[1]))){
    if(!live.has(c)){console.log('죽은 소집: '+nm+' → '+c+(arc.has(c)?' (보관됨)':' (없음)'));dead++;}
    else if(!rostered.has(c)&&rostered.has(nm)){console.log('대기자 호출: '+nm+' → '+c);bench++;}
  }
}
console.log('죽은 소집 '+dead+'건 · 대기자 호출 '+bench+'건');
"
```

## 2단계 · 판정 (숫자를 뜻으로 바꾼다)

| 신호 | 임계 | 뜻 | 처방 방향 |
|---|---|---|---|
| 팀 가동률 30% 미만 | 🔴 | 편성이 과하다 | 대기로 내리거나 그 팀 업무를 실제로 돌려본다 |
| 30일 이상 조용한 팀 | 🔴 | 없는 팀이다 | 보관 후보 · 또는 첫 업무를 지정해 시동 |
| 확인 대기 5건 이상 · 최고령 7일 초과 | 🟡 | **사람 몫이 막혀 있다** | 확인 습관 · 알림 · 승인 단계 축소 |
| 발행 비율 20% 미만 | 🔴 | 일이 시스템 안에서만 돈다 | 마지막 1미터(발행 경로) 수리 |
| 죽은 소집 1건 이상 | 🔴 | 하네스가 부르면 깨진다 | 대체자 지정 또는 그 단계 제거 |
| 성장 트리거 임계 도달 | 🟢 | 팀을 늘릴 때다 | `download team` 으로 넘긴다 |
| 팀 규칙 0개 (2주 이상) | 🟡 | 피드백이 안 쌓인다 | 업무 끝에 "규칙으로" 한 번 |

## 4단계 · 다음으로 넘기기 (**월간만**)

주간은 여기까지 오지 않는다. 그 주에 처리하고 끝낸다.

| 결론 | 넘기는 곳 |
|---|---|
| 팀을 새로 만들어야 한다 | 「팀 구축하자」 (`download team` 게이트) |
| 사람 하나가 없다 | 「직원 다운로드」 (`download agent`) |
| 반복 업무가 스킬이 안 돼 있다 | 「스킬 다운로드」 (`download skill`) |
| 일의 방향 자체가 의심된다 | 「방향 피드백」 (`plan-reviewer`) |
| 편성은 맞는데 안 쓴다 | 사람 몫 · 첫 업무를 지정해 시동을 건다 |

## 하지 말 것

- 가동률이 낮다고 **바로 보관하지 않는다.** 안 쓴 이유가 "필요 없어서"인지 "돌릴 줄 몰라서"인지 먼저 가른다.
- 실측이 없는 항목을 "양호"로 적지 않는다. **측정 안 됨**이라고 쓴다.
- 처방을 4개 이상 늘어놓지 않는다.
- **주간에 조직 개편을 제안하지 않는다.** 매주 편성을 흔들면 팀이 자리를 못 잡는다.
- 주간인데 월간 규격(성장 트리거·⏸ 승인)으로 길게 쓰지 않는다. **주간은 1~2분이다.**
