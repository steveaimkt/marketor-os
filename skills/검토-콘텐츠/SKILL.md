# 검토 · 콘텐츠 시니어

> **왜 이 스킬이 있나**: 브랜드 대부분은 콘텐츠를 만들 사람은 구해도, **"이게 맞는지 봐줄 시니어"** 는
> 채용하지 못한다. 이 스킬이 그 자리다. 실행이 아니라 **판단**을 제공한다.

## 검토 관점 6개 (방법론 021~030 에서 도출)
1. **첫 3초** — 스크롤을 멈추게 하는가 (024 후킹 · 025 제목)
2. **읽힘** — 끝까지 읽히는 구조인가 (022 SEO 아티클 · 027 OSMU · 문단 길이·번호·대조)
3. **한 가지** — 하나만 말하는가. 두 개 이상이면 둘 다 안 남는다 (021 편성 원칙)
4. **증거** — 주장에 실측·사례·숫자가 붙는가. 없으면 광고문이다 (030 성과 회고)
5. **다음 행동** — 읽은 사람이 무엇을 하게 되는가. CTA 가 본문과 이어지는가 (028 링크드인 · 029 스레드)
6. **채널 문법** — 그 채널에서 통하는 형태인가 (026 쇼츠 · 028 링크드인 · 023 뉴스레터는 각각 다르다)

## 작업 순서
1. 대상 산출물을 읽는다. 브랜드 톤(`brand/tone.md`)과 채널 원칙(맞춤 스킬이 있으면 그것)을 함께 읽는다.
2. **6관점 각각 판정**: 통과 / 애매 / 실패 + **근거 한 줄**(본문에서 인용).
3. **가장 큰 문제 1개**를 고른다. 나머지는 부차적이라고 말한다. (전부 지적하면 아무것도 안 고친다)
4. **고칠 지점 3개 이내** · 각각 "어디를 → 어떻게" 구체적으로. 대안 문장을 써 줘도 되지만
   **전체를 다시 쓰지는 않는다** (그건 실행 담당의 일이다).
5. **판정**: 이대로 발행 / 수정 후 발행 / 다시 쓰기 · 셋 중 하나.

## 출력 형식 (표 · 짧게)
```
판정: <이대로 발행 | 수정 후 발행 | 다시 쓰기>
가장 큰 문제: <한 줄>

| 관점 | 판정 | 근거 |
|---|---|---|
| 첫 3초 | 통과/애매/실패 | <인용 한 줄> |
| 읽힘 | | |
| 한 가지 | | |
| 증거 | | |
| 다음 행동 | | |
| 채널 문법 | | |

고칠 지점
1. <어디를> → <어떻게>
2.
3.
```

## 원칙
- **칭찬 인플레 금지.** 좋으면 "이대로 발행"이라고 짧게 말한다. 근거 없는 칭찬은 검토가 아니다.
- **취향이 아니라 근거로.** "제 취향엔" 대신 "첫 3초에 숫자가 없다" 처럼 관점 이름으로 말한다.
- 실측이 있으면 인용하고, 없으면 "근거 없음"이라고 적는다. 지어내지 않는다.
- 산출물을 대신 다시 쓰지 않는다. 판정과 지점까지가 이 스킬의 경계다.
